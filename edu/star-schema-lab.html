1. What a star schema is

A fact table records events (one row per order); dimension tables describe the who/what/when. Real star schemas keep facts narrow & additive so BI tools query fast:

fct_orders — the fact: order_id, date, customer_id, product_id, total
dim_customer — customer_id, name, region
dim_product — product_id, name, category
dim_date — date, year, month, quarter

A fact references dimensions by key — that's the "star" shape. This is the model my retail-analytics-dashboard project uses.

3. Why it matters — the KPI query

Once the schema is right, business KPIs are a short, fast query:

SELECT d.month,
       SUM(f.total)          AS revenue,
       COUNT(*)              AS order_lines
FROM fct_orders f
JOIN dim_date     d ON f.order_date_id = d.date_id
GROUP BY d.month;

The fact table carries the numbers; dimensions carry the labels — so adding "by region" or "by category" is a one-line JOIN, not a rewrite.
